# 1. Теоретическая часть
## 1.1. Веб-приложения
Веб-приложение — это программное обеспечение, которое работает через веб-браузер и позволяет пользователю взаимодействовать с сервером посредством интернета или локальной сети. В отличие от обычных программ, веб-приложение не обязательно требует установки на компьютер пользователя. Для работы достаточно браузера и доступа к серверу.

Веб-приложения обычно состоят из клиентской и серверной частей. Клиентская часть отвечает за отображение информации, формы, кнопки и взаимодействие с пользователем. Серверная часть обрабатывает запросы, проверяет данные, выполняет операции с базой данных и возвращает пользователю результат.

В данной работе используется традиционная архитектура веб-приложения, в которой браузер отправляет HTTP-запросы серверу, а сервер обрабатывает их с помощью PHP и возвращает HTML-страницы.
## 1.2. Клиентская и серверная части
Клиентская часть приложения реализована с использованием HTML и CSS.
- HTML (HyperText Markup Language) используется для создания структуры веб-страниц, форм, таблиц, заголовков и других элементов.
- CSS (Cascading Style Sheets) используется для оформления страниц, определения цветов, размеров, отступов, расположения элементов и внешнего вида интерфейса.
Серверная часть реализована с использованием языка PHP. PHP выполняет обработку форм, проверку данных, регистрацию пользователей, аутентификацию, управление ролями и взаимодействие с базой данных.
## 1.3. PHP
PHP — серверный язык программирования, предназначенный в том числе для разработки динамических веб-приложений. Код PHP выполняется на сервере, а браузеру отправляется результат его выполнения, обычно в виде HTML.

В разработанном приложении PHP используется для:
- обработки регистрации и входа пользователей;
- проверки введённых данных;
- обработки формы добавления фильмов;
- поиска фильмов;
- выполнения запросов к базе данных;
- управления пользовательскими сессиями;
- проверки прав доступа;
- выполнения административных операций.
## 1.4. База данных SQLite
SQLite — это реляционная система управления базами данных, которая хранит данные в одном файле. Она не требует отдельного сервера баз данных, что делает её удобной для небольших проектов, учебных работ и локальных веб-приложений.

В проекте используется SQLite для хранения информации о пользователях и фильмах. Данные сохраняются в файле базы данных, что позволяет сохранять информацию между запусками веб-приложения.
## 1.5. PDO
PDO (PHP Data Objects) — интерфейс PHP для взаимодействия с базами данных. Он предоставляет единый способ подключения и выполнения SQL-запросов для разных систем управления базами данных.

В проекте PDO используется для подключения к SQLite, выполнения запросов SELECT, INSERT, UPDATE и DELETE.

Для защиты от SQL-инъекций используются подготовленные запросы (Prepared Statements). Они позволяют передавать пользовательские данные отдельно от SQL-команды, что снижает риск выполнения вредоносного SQL-кода.
## 1.6. Аутентификация и авторизация
Аутентификация — процесс проверки личности пользователя, например, посредством логина и пароля.

Авторизация — процесс определения доступных пользователю действий и ресурсов на основании его прав.

В приложении реализована регистрация, вход и выход из системы. После входа пользователь получает доступ к защищённым разделам. Для административных функций предусмотрена отдельная роль admin.

Обычный пользователь имеет роль user, а администратор обладает дополнительными правами на управление фильмами и пользователями.
## 1.7. Сессии
Сессия — механизм хранения информации о состоянии пользователя между HTTP-запросами. Поскольку HTTP сам по себе не хранит состояние взаимодействия между запросами, сессии позволяют приложению помнить, что пользователь успешно вошёл в систему.

В PHP сессии реализуются с помощью session_start() и переменных массива $_SESSION.

В проекте сессии используются для хранения информации об авторизованном пользователе и его роли. Это позволяет проверять доступ к защищённым страницам.
## 1.8. Безопасность веб-приложений
При разработке веб-приложений необходимо учитывать потенциальные угрозы, связанные с пользовательскими данными и доступом к ресурсам.

В проекте применяются следующие методы защиты:
- проверка пользовательских данных;
- хеширование паролей;
- подготовленные SQL-запросы;
- защита страниц с помощью сессий;
- проверка роли администратора;
- экранирование выводимого HTML;
- CSRF-токены для защиты форм от нежелательных запросов.

## 4.4. Функциональные возможности
### 4.4.1. Публичный компонент
Главная страница приложения доступна всем посетителям, включая пользователей, которые не зарегистрированы и не вошли в систему.

Информация о фильмах загружается из базы данных SQLite посредством серверных запросов PHP. Для отображения информации используются динамически формируемые HTML-элементы.

При первоначальном запуске приложение автоматически добавляет несколько демонстрационных фильмов, если таблица фильмов пустая. Это позволяет сразу проверить работу каталога без необходимости вручную добавлять записи.

В демонстрационной базе предусмотрены следующие фильмы:
Название	Год	Жанр	Рейтинг
Interstellar	2014	Sci-Fi	8.7
The Matrix	1999	Sci-Fi	8.7
Titanic	1997	Romance	7.9
Inception	2010	Sci-Fi	8.8
The Shawshank Redemption	1994	Drama	9.3

Таким образом, требование наличия минимум 2–3 динамических элементов контента, извлекаемых из базы данных, выполняется.
### 4.4.2. Регистрация пользователя
Страница регистрации позволяет создать новую учётную запись.

Для регистрации пользователь вводит:
- имя пользователя;
- адрес электронной почты;
- пароль;
- подтверждение пароля.
После отправки формы сервер проверяет корректность введённых данных, формат электронной почты и наличие уже зарегистрированного пользователя с таким именем или адресом.

Если регистрация успешна, информация сохраняется в базе данных, а пользователь получает стандартную роль user.

Пароль не сохраняется в открытом виде. Перед записью в базу данных используется функция password_hash(), которая создаёт безопасный парольный хеш.

**Скриншот необходимо добавить:** 2 — форма регистрации.
### 4.4.3. Авторизация пользователя
Страница входа позволяет зарегистрированному пользователю войти в систему.

Пользователь может указать имя пользователя или электронную почту и пароль. PHP выполняет поиск соответствующей записи в базе данных и проверяет введённый пароль с помощью функции password_verify().

При успешной авторизации в сессии сохраняются идентификатор пользователя и его роль. Эти данные используются для предоставления доступа к защищённым страницам.

При неправильном логине или пароле приложение выводит сообщение об ошибке.

**Скриншот необходимо добавить:** 3 — форма авторизации.
### 4.4.4. Форма добавления фильма
Форма добавления фильма доступна только авторизованным пользователям.

Она содержит пять основных полей разных типов:
Поле	Тип	Описание
Название	Text	Название фильма
Год выпуска	Number	Год выпуска фильма
Жанр	Select	Выбор жанра из списка
Рейтинг	Number	Рейтинг фильма от 0 до 10
Описание	Textarea	Текстовое описание фильма

При отправке формы сервер выполняет проверку данных:
- название и описание должны быть заполнены;
- год должен быть целым числом в допустимом диапазоне;
- жанр должен соответствовать одному из доступных вариантов;
- рейтинг должен быть числом от 0 до 10.
Если данные не соответствуют требованиям, пользователь получает сообщение об ошибке и может исправить введённые значения.

При успешном добавлении информация сохраняется в базе данных. Также сохраняется идентификатор пользователя, который добавил фильм.

Таким образом, форма соответствует требованию создания ресурса с минимум пятью полями различных типов, проверкой данных и обработкой ошибок.

**Скриншот необходимо добавить:** 4 — форма добавления фильма.
### 4.4.5. Форма поиска

## 4.7. Безопасность приложения
Безопасность является важной частью разработки веб-приложений, поскольку пользователь может вводить некорректные или специально подготовленные данные, пытаться получить доступ к чужим ресурсам или выполнять неразрешённые операции.

В разработанном приложении используются следующие механизмы защиты.
### 4.7.1. Проверка входных данных
Данные проверяются на стороне сервера перед их сохранением в базе данных.

При добавлении и редактировании фильмов проверяется корректность года выпуска, рейтинга, жанра и обязательных текстовых полей.

Также в HTML-формах используются атрибуты, позволяющие браузеру выполнять предварительную проверку, например required, min, max, step и type="number".

Клиентская проверка улучшает взаимодействие с пользователем, но не заменяет серверную проверку, поскольку клиентские ограничения могут быть обойдены.

**Клиентская валидация** выполняется браузером до отправки формы. В проекте для неё используются HTML-атрибуты `required`, `min`, `max`, `step` и `type="number"`. Например, браузер может не разрешить отправить пустое обязательное поле или число, выходящее за указанный диапазон.

**Серверная валидация** выполняется PHP после получения запроса. Сервер повторно проверяет обязательные поля, допустимый год выпуска, жанр и рейтинг от 0 до 10. Только после успешной серверной проверки данные сохраняются в SQLite. Именно серверная проверка является обязательной, поскольку HTML-ограничения можно изменить в браузере или обойти прямым HTTP-запросом.

Таким образом, клиентская проверка помогает пользователю быстрее исправлять ошибки, а серверная защищает целостность данных.

### 4.7.2. Хеширование паролей
Для безопасного хранения паролей используется функция PHP password_hash().

В базе данных сохраняется не исходный пароль, а его хеш. При входе в систему введённый пароль проверяется с помощью password_verify().

Это позволяет избежать хранения паролей в открытом виде и снижает последствия возможного доступа к базе данных.
### 4.7.3. Защита от SQL-инъекций
Для выполнения SQL-запросов используются подготовленные запросы PDO.

Пример:
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE username = ?'
);

$stmt->execute([$username]);


В данном случае пользовательское значение передаётся отдельно от SQL-команды. Это позволяет избежать ситуации, когда введённые данные воспринимаются как часть SQL-кода.
### 4.7.4. Экранирование HTML
Для безопасного вывода данных применяется функция htmlspecialchars().

В проекте создана вспомогательная функция e(), которая преобразует специальные HTML-символы в безопасные представления.

Это помогает защитить приложение от XSS-атак (Cross-Site Scripting), при которых злоумышленник может внедрить вредоносный HTML или JavaScript в содержимое страницы.
### 4.7.5. Управление доступом
Для управления доступом используются PHP-сессии и проверки ролей.

Функция require_login() проверяет, авторизован ли пользователь. Функция require_admin() проверяет, имеет ли текущий пользователь роль администратора.

Если пользователь не имеет необходимых прав, доступ к защищённой странице блокируется.

**Как проверить использование сессий:**

1. Запустить приложение и войти под зарегистрированным пользователем.
2. Открыть инструменты разработчика браузера (`F12`), перейти в раздел `Application` → `Cookies` и проверить наличие cookie `PHPSESSID` (в Chrome/Chromium).
3. Открыть защищённую страницу, например `add_movie.php`, и убедиться, что после входа она доступна.
4. Выйти из аккаунта и повторно открыть эту страницу. Доступ должен быть заблокирован или пользователь должен быть перенаправлен на страницу входа.
5. Войти под обычным пользователем и попробовать открыть `admin.php`. Ожидаемый результат — отказ в доступе.
6. Повторить проверку под администратором. Административная панель должна быть доступна.

Наличие cookie `PHPSESSID` само по себе ещё не доказывает корректность разграничения доступа. Важно также проверить поведение защищённых страниц до входа, после входа и после выхода.

В проекте для управления доступом используются **сессии**, а не токены авторизации. CSRF-токен выполняет другую задачу: защищает формы от поддельных межсайтовых запросов и не заменяет проверку личности и роли пользователя.

### 4.7.6. CSRF-защита
Для форм, выполняющих операции изменения данных, используются CSRF-токены (Cross-Site Request Forgery).

Токен создаётся с помощью генератора случайных данных и хранится в сессии. При отправке формы сервер проверяет, соответствует ли полученный токен сохранённому.

Это помогает предотвращать выполнение нежелательных действий от имени авторизованного пользователя через сторонние страницы.

## 5.2. Запуск приложения
Для запуска проекта необходим установленный PHP с поддержкой PDO SQLite.

Проект можно запустить с помощью встроенного веб-сервера PHP.

Команды запуска в Windows PowerShell:
cd "$HOME\Desktop\univer\PHP\movie_catalog"


Если проект находится во вложенной папке:
cd .\movie_catalog


Проверка версии PHP:
php -v


Проверка доступных расширений:
php -m | findstr /I "PDO sqlite"


Проверка драйвера SQLite для PDO:
php -r "print_r(PDO::getAvailableDrivers());"


Запуск веб-сервера:
php -S localhost:8000


После запуска приложение доступно по адресу:

http://localhost:8000

При первом обращении к приложению создаётся база данных и таблицы. Если таблица movies пустая, в неё добавляются демонстрационные фильмы.
## 5.3. Первоначальное создание администратора
При регистрации нового пользователя его роль по умолчанию устанавливается как user.

Для первоначального назначения роли администратора используется SQL-команда:
UPDATE users
SET role = 'admin'
WHERE username = 'admin';


После этого необходимо повторно войти в систему, чтобы обновлённая роль была загружена в сессию.

В дальнейшем новые административные аккаунты можно создавать через страницу create_admin.php, доступную только администраторам.

# 7. Ответы на контрольные вопросы
Ниже приведены примерные контрольные вопросы по проекту и ответы на них. Если преподаватель предоставит отдельный список вопросов, этот раздел необходимо будет адаптировать под него.
1. Что такое веб-приложение?
Веб-приложение — это программное обеспечение, которое работает через браузер и взаимодействует с сервером. Оно позволяет пользователю выполнять действия, получать и изменять информацию без необходимости устанавливать отдельную программу на компьютер.
2. Чем отличается клиентская часть от серверной?
Клиентская часть отвечает за интерфейс, отображение информации и взаимодействие с пользователем. Серверная часть обрабатывает запросы, выполняет проверки, работает с базой данных и формирует ответ.
3. Для чего используется PHP в данном проекте?
PHP используется для регистрации и авторизации пользователей, обработки форм, поиска фильмов, проверки прав доступа, выполнения SQL-запросов и формирования динамических страниц.
4. Что такое SQLite?
SQLite — это система управления реляционными базами данных, которая хранит данные в одном файле и не требует отдельного серверного процесса. В проекте она используется для хранения пользователей и фильмов.
5. Что такое PDO?
PDO — это интерфейс PHP для взаимодействия с базами данных. Он позволяет подключаться к базе данных, выполнять SQL-запросы и использовать подготовленные запросы для повышения безопасности.
6. Что такое SQL-инъекция?
SQL-инъекция — это тип атаки, при котором злоумышленник пытается внедрить SQL-код через пользовательский ввод, чтобы изменить поведение запроса или получить доступ к данным.

Для защиты в проекте используются подготовленные запросы PDO.
7. Что такое аутентификация и авторизация?
Аутентификация — проверка личности пользователя.

Авторизация — проверка того, какие действия пользователь имеет право выполнять.

В проекте аутентификация осуществляется при входе по логину или электронной почте и паролю, а авторизация зависит от роли пользователя.
8. Для чего используется хеширование паролей?
Хеширование позволяет хранить пароль в виде преобразованного значения, а не в открытом виде. В PHP для этого используются password_hash() и password_verify().

В проекте пароли пользователей и администраторов хранятся в виде хешей.
9. Что такое сессия?
Сессия позволяет сохранять информацию о пользователе между HTTP-запросами. В проекте сессия используется для хранения идентификатора пользователя и его роли после авторизации.
10. Что такое CRUD?
CRUD — это четыре основные операции управления данными:
- Create — создание записей;
- Read — чтение и просмотр;
- Update — обновление;
- Delete — удаление.
В административной части приложения CRUD-операции используются для управления фильмами.
11. Что такое XSS?
XSS (Cross-Site Scripting) — атака, при которой злоумышленник внедряет вредоносный код в веб-страницу, чтобы он выполнялся в браузере других пользователей.

Для снижения риска XSS в проекте применяется экранирование HTML-данных с помощью htmlspecialchars().
12. Что такое CSRF?
CSRF (Cross-Site Request Forgery) — атака, при которой злоумышленник пытается заставить авторизованного пользователя выполнить нежелательное действие на сайте.

В приложении используется CSRF-токен, который проверяется сервером при отправке защищённых форм.
13. Почему проверку данных необходимо выполнять на сервере?
Проверка на клиенте может быть обойдена, поскольку пользователь может изменить HTML, отключить JavaScript или отправить запрос напрямую.

Поэтому серверная проверка является обязательной. Она позволяет контролировать данные независимо от клиентского интерфейса.
14. Что такое первичный и внешний ключ?
Первичный ключ — поле, которое уникально идентифицирует запись в таблице.

Внешний ключ — поле, которое связывает запись одной таблицы с записью другой таблицы.

В проекте users.id и movies.id являются первичными ключами, а movies.created_by является внешним ключом, связанный с users.id.
15. Для чего используется Git и GitHub?
Git — система контроля версий, которая позволяет сохранять изменения в проекте, отслеживать историю и возвращаться к предыдущим версиям.

GitHub — платформа для хранения Git-репозиториев в интернете, публикации проектов и совместной разработки.
